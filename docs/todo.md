## P0 · 日常使用短板（小-中工作量，直接补可用性）

- [x] **1. 开机自启（含静默启动到托盘）**（2026-10-22 已实现，待用户验收）
  托盘常驻工具的标配。注册表 Run 项（或启动文件夹快捷方式）+ `--minimized` 启动参数（当前启动必弹主窗口和气泡）。设置页加开关。
  > 实现注记：HKCU Run 键（免管理员），仅当条目指向当前 exe 时视为已启用（换目录重新勾选即重写）；`--minimized` 静默驻留托盘、不弹窗口和气泡。

- [x] **2. 全局「暂停闪避」总开关**（2026-10-22 已实现，待用户验收）
  托盘菜单 + 主界面一键临时停用全部规则；暂停时立即恢复所有被压音量（复用退出还原链路）。现在只能逐条禁用规则或退出程序。典型场景：临时听清被压低的应用、演示。
  > 实现注记：引擎 `SetSuspended`（暂停＝即时还原到原始锚点并清闪避状态；恢复＝以真实音量重起基准）。入口三处同步：托盘菜单勾选项、设置页「启用闪避」开关、顶栏琥珀「闪避已暂停」徽章（仅暂停时出现）。已验证：暂停立即还原、触发持续时恢复会重新闪避。

- [x] **3. 诊断与自查渠道**（原「界面内事件日志」，定位已修正）（2026-10-22 已实现，待用户验收）
  - **定位（审核结论）**：诊断的责任主体是程序和维护人员，不是用户的日常任务；本功能是"提供信心"的自查渠道。**未触发时不占界面**，不能作为核心内容大面积出现。
  - 主动提示（随错误出现，不常驻）：配置未生效时程序主动给出原因，如"规则 N 的触发应用 xxx 未运行 / 名字与实际进程不符（参考：哔哩哔哩）""分组 xx 当前无成员进程在运行"。
  - 隐蔽入口：设置页角落或托盘菜单二级项 → 完整事件日志（最近 N 条：规则触发/解除、匹配失败、设备切换），供自查与反馈附档。
  - 背景案例：B站中文名静默失效当时靠 `Console --log` 才定位，普通用户无任何诊断手段。
  > 实现注记：① 主动提示——规则列表行内 ⚠ 琥珀提醒（触发/目标应用无会话、分组已删除，随会话变化重算）+ 引擎侧"配置问题"一次性预警（坏引用规则）；② 隐蔽入口——设置页底部弱化文字入口 + 托盘菜单「事件日志」，展开只读面板（内存环形缓冲最近 600 条：规则生效/解除按轮去重、设备切换、暂停/恢复、配置问题、运行/引擎/监控日志），可复制/清空，不落盘不弹窗。

- [ ] **4. 通信设备覆盖 / 设备选择**
  目前仅跟默认播放设备（Multimedia 角色），通话走独立耳机的场景完全不覆盖（README 已知限制第 1 条）。最小版本：支持跟随"默认通信设备"；完整版本：设备选择器。影响面最大、工作量也最大。

## P1 · 规则表达力（产品迭代主线）

- [ ] **5. 规则级闪避时长覆盖**
  FadeOut/FadeIn 目前为全局设置；规则加可选时长字段，留空 = 跟随全局，兼容旧配置。场景：视频压音乐快进快出、游戏压慢放慢收。

- [ ] **6. 规则生效条件**
  如"仅当某输出设备激活时""仅时间段内生效"。最小版本先做一种条件（设备条件最实用：耳机/音箱两套行为）。

- [ ] **7. 多规则叠加语义**
  同目标多条规则命中时现取优先级最高者；备选"取闪避最深者"（20% 与 40% 同时命中压到 20%）。规则级开关，小改动。

- [ ] **8. 手动接管模式**
  已知限制第 4 条（闪避期间手动调音量被渐变覆盖，现仅更新恢复目标）。可加选项：用户手动调节即视为接管，该会话本轮闪避不再干预，直到下次触发。

## 实验性（先探针验证，再决定立项）

- [ ] **14. 「暂停目标应用」作为闪避替代动作**
  看视频时直接暂停音乐播放器（而非压音量），视频停了自动恢复播放。第三方经 SMTC 请求暂停支持有限，大概率需向目标应用发送媒体键，可靠性存疑——先做可行性探针，再决定。

## 长期方向（单独立项评估，不排入常规迭代）

- [ ] **15. 多端适配（macOS / Linux）**
  目标：不能只用于 Windows。
  现实约束：音频层 WASAPI（NAudio）为 Windows 专属——macOS 需 CoreAudio、Linux 需 PipeWire/PulseAudio，会话监控与音量控制层需按平台整体重写；UI 层 WPF 同为 Windows 专属，需换跨平台框架（如 Avalonia）或分平台实现。Tuner.Core 中规则引擎、配置、音量曲线等 UI 无关部分可直接复用。工程量约等于按平台重做核心层，需单独立项评估。
